# Environment profiles

| Profile | Configuration | Data/services | Verification |
|---|---|---|---|
| Local shell | APP_ENV=development, SERVICES_ENABLED=false | No private data; protected endpoints unavailable | Build, UI and isolated unit tests |
| Local integrated | APP_ENV=development, SERVICES_ENABLED=true | Local Supabase/PostgreSQL/test SMTP, synthetic fixtures | Real local integration tests |
| Staging | APP_ENV=staging, SERVICES_ENABLED=true, HTTPS | Isolated hosted dependencies and synthetic identities; current app/scanner compute is temporarily on the Mac | Selected real Supabase/browser/security checks pass; cloud runtime and complete release gates remain |
| Production | APP_ENV=production, SERVICES_ENABLED=true, HTTPS | Separate secrets and approved production services | Authorized release and safe smoke checks |

The current zero-paid-service profile uses Supabase Free (Auth/PostgreSQL/private Storage), Mailtrap Email Sandbox Free, the native Mac scanner/application and a temporary Cloudflare Quick Tunnel. Private runtime, operator and synthetic-test credentials are separated. AI stays disabled/FAQ-only; contact sending stays disabled until a reviewed header-replacing proxy is configured. Console telemetry and local scheduling are not hosted operational verification. See `../docs/deployment.md#current-free-staging` and `../docs/verification/free-staging-result.json` for observed checks, quotas, process dependencies and remaining gates. The Mac must remain awake; restarting a Quick Tunnel changes its hostname and requires coordinated app/Auth URL updates.

The initial profile, hybrid Azure Blob, independent Azure AI and Key Vault secrets adapters are implemented in source. They have local SDK/HTTP/database/configuration contract tests, not live Azure verification. Supabase remains the default authentication option, Entra is selectable in source, and persistence remains PostgreSQL; each provider selector is independent. See `../docs/azure-storage.md`, `../docs/azure-support.md` and `../docs/azure-secrets.md` for prerequisites and staging gates. SMTP is the selected Azure-hosted email option; the project brief records ACS Email retirement. Container image/Compose and Azure foundation/storage/monitoring/workload/job/access templates are present, with offline compilation/configuration checks; image execution and cloud deployment remain unverified. The foundation defines private vault networking, identities, registry and environment log routing; optional storage defines its account/private containers and soft-delete retention. See `../docs/deployment.md` for private-runner access and deployment order. Entra client identity, remaining service-specific Azure resource provisioning, live managed-identity telemetry ingestion, complete/verified alert coverage and real foundation/storage connectivity remain incomplete. Replica/5xx alert source and its staging/incident runbook are in `../docs/azure-monitoring.md`; source definitions do not establish live notifications. Changing provider configuration or DATABASE_URL does not migrate identities, RLS or files.

## Entra source profile selection

`AUTH_PROVIDER=entra` is selectable in source with the validated settings in `.env.example` and `docs/azure-identity.md`. Environment and pinned Key Vault secrets support independent login/directory credentials and the MFA encryption keyring. Supabase credentials are conditional on selecting Supabase authentication/storage. This does not migrate identities, provision a tenant, grant consent or configure hosted SSPR. Existing infrastructure examples are not proof of a configured Entra workload; live tenant, browser, account recovery and full staging gates remain required before advertising a supported Azure profile.

## Operational telemetry source selection

`OBSERVABILITY_PROVIDER=azure_monitor` selects a bounded private OpenTelemetry provider for fixed application operational events. It requires an approved regional connection setting and `APPLICATION_INSIGHTS_NO_STATSBEAT=true`; pinned Key Vault resolution is supported. Console is still the default. No Application Insights resource is provisioned by selection. Source requires Entra-authenticated ingestion through explicit managed identity (Azure CLI only in development/test), with bounded token acquisition and no key-only fallback. Typed workload selectors and a synthetic Entra/Blob/monitor example are present. The access template optionally prepares resource-scoped Monitoring Metrics Publisher for the web identity on an existing Application Insights resource. Applied roles, disabled local-auth policy, live token/ingestion/query evidence, hosted drain, full alert coverage and notifications remain gates. See `../docs/azure-monitoring.md`.

## Supabase database scheduler

The current free Supabase staging profile can select `SCHEDULER_PROVIDER=database` after an owner installs the reviewed pg_cron operation. This uses the existing PostgreSQL maintenance capability directly and needs no `CRON_SECRET`; the HTTP scheduler endpoint stays unavailable. Use `docs/database-scheduler.md` for guards, cadence, privilege checks, pausing/recovery and separate real-execution evidence. This does not replace web hosting, file scanning or monitoring/alert delivery, and does not claim that an example configuration installs a job.
